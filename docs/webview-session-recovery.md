# 0.4.2 教务网页会话恢复

设备截图显示会话恢复失败后停留在空白 WebView，读取按钮仍可点击并报域名错误。发现桥接代码调用 CampusHttp.restore 过滤过期 Cookie 后，再次读取加密存储的原始 Cookie 列表，导致过滤结果丢失。Android CookieManager 对其中任何记录返回 false 时，旧实现会让整次恢复失败；真实设备是否因此失败需新版验证。

桥接改为传递已恢复的有效记录，过滤 Expires 已到期与 Max-Age <= 0 的删除记录，保留 Secure、HttpOnly、Domain 和 Path。缺失或全部过期的会话明确要求重新认证。原生写入失败保留错误状态，避免把写入失败当作登录成功。

重试重新运行会话恢复与教务入口加载；错误横幅提供原生 CAS 重新认证，完成后同步当前账号并重新打开教务页。仅在教务域名主页面完成加载且无加载错误时启用读取，失败时保留课程缓存。跳回 CAS 页面时提示重新认证。

回归测试覆盖有效与过期/删除记录混合、会话缺失、会话全部过期、原生 Cookie 拒绝四条路径。真实学校账号、服务器会话过期及页面布局仍需设备验证。继续保留 0.4.1 的原生库解压和 WorkManager 反射规则。
